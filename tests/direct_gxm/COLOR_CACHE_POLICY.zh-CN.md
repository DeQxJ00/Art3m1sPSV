# 色调效果的缓存策略

灰度、颜色乘算和 sepia 通过原始 shader 内容校验获得逐像素色调能力，统一使用已有的结果、输入和移动缓存。脚本给效果起的名字不构成能力证明；未知 shader 保留完整的屏幕空间依赖检查。

| 变化 | 处理 |
| --- | --- |
| 输入、参数及变换都不变 | 复用最终结果 |
| 仅效果参数改变，输入不变 | 复用输入，重新执行原 shader |
| 整组平移、采样相位不变 | 在缓存覆盖范围内复用移动结果 |
| 半像素等采样相位变化 | 保留原渲染路径，避免对已量化的色调结果再次插值 |
| 缩放、源图内容、局部层位置或颜色变化 | 缓存失效；稳定后重新准入 |
| mask、用户纹理、非单位效果 alpha 或未验证效果 | 保留原隔离及依赖检查 |

颜色乘算和 sepia 还要求 RGB 参数明确且在 `[0,1]` 内。带加性偏移的效果不自动获得这一能力。原 shader、RGBA8 中间结果和图层混合顺序不变；连续缩放不通过忽略变换来强行命中缓存。已证明中性的父分组可以省去冗余合成，原色调 pass 仍执行。

移动结果沿用现有的一组有界缓存、内容与 shader 修订号、稳定观察准入、显存压力退出和 GPU 资源生命周期。单张背景和多层组合采用同一套能力规则，不按场景配置缓存。

## 验证

- Rust 原生效果测试 69 项通过，包含三类色调的单层/多层准入、未知来源拒绝、用户纹理/alpha 拒绝和 shader 替换撤销能力。
- C++ 缓存测试通过，包括 1185 项坐标及失效检查，以及新增的整数/亚像素相位检查。
- 实机探针已扩展为灰度、颜色乘算、sepia，并比较原路径与缓存路径；覆盖透明层、整数移动、亚像素回退及资源/参数失效。
- 2026-10-14 实机 CPU 444 / GPU 222 下，60 项移动与失效检查全部通过，滤镜链验证通过。灰度、颜色乘算和 sepia 的最大通道差为 2/255，前景标记差异为零；亚像素移动回退正常。比较排除了左上角 400×220 的诊断覆盖区域，详细数据见 `color_cache_device_verification.json`。原设置已读回校验，正常模式启动到启动器已确认；随后游戏标题资源加载停止产出主线程帧，音频线程仍运行，原因尚未确认。已恢复上一版包并读回校验，新增版本尚未通过完整游戏验收。
- 本轮验证了缓存命中与正确性，不是原游戏低帧镜头的帧率复测。此前 sepia 冗余父分组优化的实测见 `background_zoom_verification.json`。

### 标题加载停滞的后续排查

补取日志确认开场视频已正常解码并关闭，停滞发生在菜单图片的前台等待交接；音频线程仍在运行。定时等待诊断另外发现，当前链接的 PSV pthread 库接受 `CLOCK_MONOTONIC` 属性但未保存它，期限转换使用墙上时钟，因此不能直接用 Rust `Condvar::wait_timeout` 作为设备端保护。该兼容性问题已经确认，但尚不能据此单独证明原无期限等待停滞的全部原因。

PSV 前台资源未就绪时改为释放状态锁、休眠 1 ms 后重新检查同一个完成条件。它只覆盖缓存未命中的同步等待，不进入正常渲染帧，不取消解码，也不返回半成品；后台加载仍保留现有队列与唤醒机制。资源加载测试 71 项通过，包含缺少完成通知时仍能且只能取走一次完整结果的回归测试。

设备包 `0fd34c59c2b3383fbf2b6127e4546c6f95476ebc50c404651af7a3dcc675fdd2` 已上传并读回校验。实机已通过开场视频及后续菜单图片加载，画面恢复，主线程继续产出帧；即时超时日志不再出现。此处验证不代表存档 2 模糊场景的性能验收，该场景仍需独立采样。
