# 通用效果节点输入缓存

针对 otomeriron 马赛克后“三组模糊输入＋外层变化”的重复绘制，将原马赛克专用输入缓存推广到递归效果节点。shader 源码、GXP、颜色运算和原有 GPU 同步边界保持原样。

## 缓存内容与失效

- 保存已有离屏节点的**输入 RGBA 画面**；这个画面已经包含子节点执行完的效果。当前节点自己的 shader、参数、透明度、纹理遮罩和输出裁剪仍实时应用。
- 不根据 shader 名称实现不同缓存。已注册的外置／内置效果都可复用输入；含多个子效果的合成节点也可保留子效果结果。单个效果的简单外层继续使用原来的省略规则，避免重复隔离。
- 输入命令、子节点效果／参数／裁剪、依赖纹理内容版本、程序注册版本或画布尺寸变化会使输入失效。父节点之外的命令插入不应因绝对命令索引变化而失效。
- 命中比较不克隆节点或参数表。缓存未命中、输入刚变化时可以先观察一帧，让子节点独立复用；稳定后再保留父节点输入。
- E-mote、网格、stencil、当前节点的命令式遮罩以及超过 4096 条输入／遮罩命令的节点，暂不接入这条缓存路径，继续原有绘制。

## 容量、槽位和稳定画面

统一使用 5 个 960×544 RGBA 离屏缓存槽（CDRAM 分配合计约 10 MiB），对应原来的 4 个最终合成槽＋1 个马赛克输入槽，没有按效果种类增加缓存池。工作离屏、显示缓冲和纹理缓存仍按原方案管理，不包含在这 10 MiB 内。

每个物理槽有独立内容版本，最终合成、输入和文字覆盖层分别保存版本引用。任一用途重写槽位都会使其他用途的旧引用失效。本帧已提交或正在构建的槽位不参与递归覆盖；交换目标前仍等待 GPU 完成。

遍历前保护本帧仍能命中的输入，避免最终合成缓存抢占它。最终画面连续稳定 24 次后允许回收一个输入槽，防止输入占满时最终合成永远无法缓存。文字覆盖层会让出仍被输入需要的第 4 槽。

## 验证方式

1. 运行 `scripts/prepare-node-cache-test.py`，在 `build/node-cache-test/fixture` 生成独立资源，不解包或修改任何安装中的游戏资源。
2. 测试包先复现马赛克参数变化、透明叠加和输入变化，再执行三组独立 H/V 模糊、外层透明度循环、单个输入移动和模糊参数变化。
3. 对照旧版 `47087a2`，分别保存 12 张图片并逐像素比较。设备 FPS 浮窗／缓存 HUD 区域不参与比较。
4. `retained-probe.once` 自检新增 `node-source-self-test`：验证首次转移、复用后 alpha、裁剪＋纹理遮罩以及嵌套父层，与原 `group_end` 路径比较。失败时关闭输入缓存路径。
5. 核心测试覆盖依赖失效、范围平移、槽位版本、满池回退、简单外层排除和最终合成不被饿死等行为。

日志中 `[node-source] hits/builds` 统计输入缓存复用／建立；它与 `[builtin-retained]` 最终合成统计不同。`effect-frame-spike.scene_us` 是绘制阶段耗时，并不等于整帧或浮窗 FPS；截图写盘长帧也不能算作效果本身耗时。

## 边界

首次出现的新图片或新效果结果仍需要绘制，首次 shader 链接、资源解码和上传也不由此缓存消除。这个方案减少相同内层效果在外层变化期间被反复执行，不保证所有首次切入都达到 60 FPS。场景真实画面仍需在实机按原录像位置验收。

CPU 333 MHz、GPU/ES4 111 MHz。旧版日志为 `build/node-cache-20260920/baseline2.log`，保留版本为 `candidate4.log`。最终包为 `build/node-cache-20260920/art3m1s_direct-v4.vpk`（这里的 v4 是本轮实验序号，不是发布版本号），SHA256：

| 检查项 | 旧版 | 通用输入缓存 |
|---|---|---|

因此，此次是重复执行的优化，不能宣称首次切入也已优化完成。首次建立的额外开销已单独保留为后续问题；继续优化应关注复用已有离屏结果／提前准备，不能取消必要 GPU 同步。

517 项核心测试通过，18 项既有忽略项。新增 4 项实机输入缓存像素自检均为最大通道差 0；原最终合成／覆盖层自检通过。

另测试过减少同帧子缓存建立的版本 `candidate5`：首次峰值有所降低，但外层每次变化又出现约 241 ms 的重复长帧，因此未采用；实机已恢复为上表的 v4 包。马赛克参数步进在保留版本未记录超过 20 ms 的效果绘制慢帧，原有优化得以保留。慢帧日志有每 5 秒记录数限制，表中范围不代表完整分位数统计。

核心补丁 `patches/generic-effect-input-cache-core.patch` 基于核心提交 `4913f78`，位于原 `mosaic-source-cache-core.patch` 之后；必须与本次 Direct host 的新槽位版本／输入缓存 ABI 一起使用。

核心提交：`91e5de0`。最终恢复部署和旧程序备份：`build/direct-deploy/deploy-20260920-104830/manifest.json`。独立测试目录已从 `games/TEST_NODE_CACHE` 移至 `validation/node-cache-20260920`，原游戏选择记录已恢复。


## 2026-09-20 实机灰度切入回归修正

用户反馈 11:15:47 录像中的五个灰度回忆场景切入仍卡顿，部分状态较旧版退步。抓取原始日志至 `build/hardware-logs/20260920-111914-companion/`，录像逐秒预览及 A/B 证据位于 `build/regression-111547/`。

查到通用输入缓存先于中性层展开执行，会把可省去的边界重新变成离屏目标；输入槽位选择也不认识仍有效的完整场景缓存。最终场景选槽又优先避让输入，导致已有场景反复被替换。修正为：

- 中性展开、局部不透明合成和单图融合优先于输入缓存。
- 标记当前有效和本帧预留的最终场景槽位，输入缓存不得覆盖这些槽位。
- 最终场景选择空闲／最久未用槽位，不因其中暂存输入而反复替换同一个场景。
- 普通静态场景在下一次相同观察时生成最终结果。对于输入完全不变、只有该节点自身输出参数变化的动画，回收该节点旧参数对应的最终画面，优先保留中间输入，并等待 24 次稳定观察再生成最终结果；原马赛克策略保留。

缓存仍为原有五个物理槽位，shader 程序、像素格式、GPU 完成等待及共享图片缓存容量未修改。

### 可复现用例与实机结果

`python scripts/prepare-gray-cache-test.py` 生成独立 fixture：合成背景、四个人物色块，各自应用真实 gray shader，七个阶段包含新增及返回既有状态。无需商业游戏资源。证据中 `device/before.log` 是用户反馈的版本，`device/after3.log` 是静态场景优先版本，均为 CPU 333／GPU 111 MHz。

- 七张阶段截图排除性能浮窗区域后逐像素一致，最大通道差 0。
- 新状态阶段 1：原记录 36.2 ms＋57.8 ms，修正后仅记录 57.8 ms。
- 新状态阶段 3：原记录 46.2 ms＋62.6 ms，修正后 35.8 ms＋57.7 ms。
- 返回状态阶段 2／4／5／6：原各有约 58 ms 的效果长帧，修正版未记录超过 20 ms 的效果绘制长帧。
- 慢帧日志限频，以上是记录到的绘制阶段耗时，不是全帧分位数，也不包含所有游戏资源首次载入情形。
- 520 项核心测试通过，18 项既有忽略。启动缓存／透明度／共享纹理像素自检通过。

曾尝试只在外层参数变化后准入输入缓存（`after.log`），重复状态改善，但首次变化约 72 ms，未采用。`after2.log` 为尚未修正最终场景选槽优先级的中间实验，也不交付。`after3.log` 的静态灰度结果改善，但嵌套模糊动画因旧参数最终结果占槽而退步；最终版本进一步增加上述输出参数动画的回收／延迟策略。

### 尚未解决的边界

首次新状态仍可能约 58 ms，不能称为完全无卡顿。实际游戏日志还包含同步读图解码，例如 `:bg/bg03as` 读取约 568 ms、解码约 577 ms；这些时间发生在绘制回调内，不能仅凭 `scene_us` 将其归为 shader 运算。需要在真实五个场景复测，并继续分别跟踪资源未命中与首次合成。

本次核心补丁 `patches/effect-cache-final-priority-core.patch` 叠加于通用输入缓存补丁之后。旧后端清理与 supplemental 目录合并未改变渲染算法。


最终候选为 `build/regression-111547/candidate5.vpk`，嵌套效果回归日志为 `device/node5.log`，12 张图与原通用输入缓存版 `candidate4`（上一轮目录）逐像素一致。中间版曾出现约 200 ms 的连续动画重绘，最终候选通过按稳定图层标识回收旧参数结果消除了这一现象。动画阶段仍有首次输入建立及后续换源的 118～160 ms 记录；最终静止窗口 300 帧／5 秒、present 约 16.4 ms。不要把静止 60 FPS 当成所有动画／首次进入都已达到 60 FPS。

最终灰度实机复核：`device/after5.log`，阶段 1 为 57.7 ms；阶段 3 为 36.0 ms＋57.7 ms；返回状态四个阶段没有记录超过 20 ms 的效果长帧。七张图与 before 逐像素一致。独立测试已从 games 移至 validation，游戏选择偏好恢复。

核心提交：`53b046d`。最终安装备份／校验记录：`build/direct-deploy/deploy-20260920-115009/manifest.json`。
