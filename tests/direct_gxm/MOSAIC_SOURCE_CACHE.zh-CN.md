# 马赛克输入缓存与合成边界优化（2026-09-20）

## 定位

用户录像 `Z:/Record/OBS/2026-09-20 07-14-09.mp4` 的马赛克转场约22–27帧，
效果结束后恢复。只读扫描本地 otomeriron PFS，定位到 `script/c20_01c.ast`
的 `0005_00010`：切换背景/近景立绘、背景 blur=10，同时执行400ms的
`colortone style=mosaic ease=in/out`。并非单纯的资源加载或shader编译。
原游戏 shader.lua 分阶段改变 `size` 参数；GXP 已内置，未发生运行时编译。
提取的研究副本仅保存在 `build/mosaic-perf-20260920/resources/`。

旧渲染路径每次参数变化，重新合成输入（包含背景模糊），并反复进行同步的离屏
切换。即使参数只保持几帧，旧最终画面缓存也会在第二帧额外烘焙，下一阶段又失效。

## 改动与边界

核心提交 `4913f78`，基于 `0f4897a`；可重放补丁为
`patches/mosaic-source-cache-core.patch`。宿主增加两个配套ABI入口，需一起构建。

- 一个固定上限的马赛克输入缓存：额外一个960×544 RGBA离屏目标，CDRAM按2MiB
  计账，不复制到CPU。只在首次需要时申请，失败回退原路径；保留现有GPU完成等待，
  完成后交换目标，不复用尚在被GPU读取的存储。
- 缓存键包括输入绘制命令、内层效果/参数、裁剪、遮罩命令、纹理内容版本、画布尺寸
  和外置程序注册代次。仅改变外层马赛克参数/输出裁剪不重建输入。动态人物、背景、
  内层模糊等发生变化时重建；清空/重注册shader后失效。不把效果按游戏名硬编码。
- 仅启用源码hash对应内置 `mosaic` 的路径；自定义同名shader、遮罩/用户纹理、
  非法size/ratio、原生E-mote及超大命令列表保持原路径。
- 重建时省略数学上中性的外层合成边界。源码确认的马赛克以及H/V模糊，只有alpha=1、
  无遮罩/用户纹理时允许；模糊另要求8个有限且在[0,1]的非负权重。着色、透明度、
  特殊混合和未知shader保持隔离。实际效果shader及原始GXP均未改。
- 含马赛克的最终画面缓存需连续稳定24次绘制才烘焙，避免每个短暂动画步骤多一次GPU等待。
  其他场景仍沿用原策略；已有匹配结果可以直接使用。

输入缓存仍是整屏RGBA，不是降低分辨率或删掉透明效果。新目标属于固定离屏内存，
不增加192MiB共享图片缓存额度，也不改变CPU堆或超频设置。

## 验证

- 509项核心测试通过，18项需外部条件的测试忽略。
- 覆盖参数更新复用、坐标/内层效果/遮罩/纹理内容/尺寸/程序变化失效，未知shader
  回退，中性边界条件，以及短步骤不烘焙、稳定后恢复最终缓存。
- Windows核心、PSV核心与Direct宿主构建成功。构建仍提示既有时钟偏差，部署已通过
  FTP回读验证新SELF，启动离屏像素自检通过。
- 实机333MHz、ES4 111MHz，对照基线为字体修正版 `eff5225` / core `0f4897a`。
  独立测试使用生成图案和透明椭圆，原内置mosaic/blur_h程序；不用商业图片。
  包含100ms及40ms参数步进、两层半透明图案、模糊变更、人物移动、删除背景和效果复位。
- 第一阶段仅缓存输入：带模糊部分**已记录慢帧**的scene_us中位数90.674→54.086ms；
  再移除中性包装层降至33.418ms。这些是慢帧日志的统计，不是全帧平均值或实际游戏FPS。
  三阶段完整证据保存在 `build/mosaic-perf-20260920/`。
- 最终稳定窗口24次绘制版：纯参数步进阶段旧版记录18条超过20ms的scene慢帧，
  新版0条；包含切换模糊/人物/透明度和截图的后半段由22条减至7条。日志每5秒最多
  记录8条，因此这是记录数而非全部慢帧计数。首次输入合成仍约35–46ms，
  后半段也仍有慢帧；不宣称实际游戏全程60帧。
- 8张截图排除左右统计浮窗后像素完全相同，包括半透明、人物位置变化、模糊变化
  以及效果复位。两张最终截图捕获到了左上性能插件，人工检查后单独排除其覆盖区域，
  不是游戏像素差异。完整比较数据为 `build/mosaic-perf-20260920/comparison.json`。
