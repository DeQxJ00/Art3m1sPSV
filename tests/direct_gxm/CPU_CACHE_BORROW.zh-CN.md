# CPU 解码缓存借用共享池余量

基线：root c7406a4 / core 002481e。用户确认让解码备份按共享池余量保留，
预载需要容量时回收，闲置 GPU 继续保持 32 MiB。

## 策略

- 堆请求仍为 320 MiB，共享缓存总额仍为 192 MiB。
- 接入共享账本的图片管理器取消固定 96 MiB 闲置总额、64 MiB CPU 备份门槛。
- 动态闲置限额 = 共享总额 − max(实际预载占用，预载预留目标)。
- CPU 备份只能使用该限额扣除现有闲置占用后的空余；准入与预载发布使用
  同一个账本锁，不把已承诺给预载的空间再次分配给备份。
- 预载仍沿用已有的 16 MiB 渐进申请，不新增等待、后台队列或轮询。
  帧间 retain 按既有优先级/LRU 释放冷数据；实际释放后加载线程才能发布。
- 闲置 GPU 上限仍为 32 MiB；压缩备份仍最多 4 MiB；类别限额不变。
- 仅保留已有 CPU 像素，不从 CDRAM 回读，不额外复制图片；当前画面及
  转场正在引用的 GPU 资源保持原来的保护方式。
- 无共享账本的独立 provider 保留原来的 96 MiB 回退策略。

浮窗 CPU 分母同步改为动态限额扣除 GPU／压缩及附加信息后的可用额度。
TOTAL 仍是 ready + idle，不是整个进程占用。主动使用的纹理、解码临时内存、
视频、音频和字体仍在共享缓存外，本修改不承诺消除首次读取或 shader 重建长帧。

## 自动验证

502 项核心测试通过，17 项忽略。

- 模拟共享池 192 MiB，ready 48 MiB、预留目标 64 MiB：CPU 备份可保留
  128 MiB，超过两个旧门槛；第 129 份备份不占用预留空间。
- 逐步发布预载至 120 MiB、预留至 136 MiB，CPU 回收到 56 MiB，GPU
  活跃 ID 不变，账本从未超过 192 MiB；预载释放后能再次增长超过 64 MiB。
- 110 张 1 MiB 图片的轮换：CPU 保留 110 MiB，闲置 GPU 保持 32 MiB；
  第一张已从 GPU 降级，再次访问直接命中解码像素，无读盘、解码或预载回调。
