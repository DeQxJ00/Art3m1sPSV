# 动作名称与脚本中断修复

故障链：脚本请求的动作名使用全角数字，模型中的同名动作使用半角数字；恢复实现漏掉了原 Win 播放器的名称归一化步骤，精确查找失败后又被宿主升级为 Lua 异常。人物更新中断，后续脚本反复引用失效的人物层，存档菜单无法正常进入。

已对比原始与压缩后现场素材：69 个动作名称及整个动作元数据完全相同；触发故障的两条人物脚本命令也相同。原始素材就存在两种数字宽度。字符串表变化为纹理尺寸描述和新增纹理格式标识，不能仅凭整个脚本或 PSB 的哈希不同认定动作被改名。

原 Win DLL 的 Play、Stop、Fade 路径在查找前调用名称转换函数。反汇编的标量分支明确将 U+FF01 至 U+FF5E 转成 U+0021 至 U+007E；两个原始驱动版本的对应机器码相同。分别执行原始机器码片段，每版 4474 个边界及随机码点与恢复规则一致。这只验证字符映射分支，不是整个原驱动的执行验证。

现在 Win 模型按此规则比较动作名，覆盖播放、状态查询、淡入淡出、停止及命名定位。没有采用临时的数字别名、精确优先或唯一候选猜测；不修改 PSB、脚本或纹理。Vita 模型仍保持原有字节比较，未将 Win 规则无证据扩展到 PSV。

宿主另外区分动作缺失与执行错误：不存在的可选动作不再升级为 Lua 异常；重复停止正常完成。非法标志、实例/线程错误及已存在动作的执行失败仍报错，并包含动作名、标志和参数。

验证：

- `emote_script_timeline_test.cpp`：缺失动作保持状态、重复停止及真实失败保留；ASan/UBSan 通过。
- 外部恢复库 `test_host_timeline.py`：全部 94 个全角 ASCII 映射、范围外字符不变、大小写不折叠、Vita 比较不变、Win 宽度混合播放/查询/淡出/停止、上下文隔离；ASan/UBSan 通过。
- 私有现场模型：原请求可启动对应动作，并能查询及停止。素材不作为测试夹具提交。
- 最终包已在实机读回校验，444/222 下自动加载存档 2，采样通过脚本/渲染错误检查，源存档及测试设置已校验恢复。该存档画面不是原故障触发点，原触发点与存档菜单仍需回归；此修复不等同于 GPU 低帧问题已解决。
