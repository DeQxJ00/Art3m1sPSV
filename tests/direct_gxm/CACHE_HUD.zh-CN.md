# 右侧缓存诊断浮窗

入口：游戏选择界面 → START 设置 → 缓存浮窗。默认关闭，○ 或左右键切换，
触摸同一行也可切换。设置保存在 `ux0:data/art3m1s-gxm/cache-hud.txt`，格式
`1 0` / `1 1`，带临时文件及备份恢复；读取错误按关闭处理并显示错误状态。

只在进入游戏后显示，不占用启动像素自检画面。右上角黑底，独立的 64×64
位图字库，不加载 TTF/OTF，不依赖游戏字体；返回启动器或关闭时释放字库。
字体和背景使用现有 GXM 绘制路径，没有额外的全屏离屏目标。

每 500 ms 读取一次快照。核心仅在开启时扫描已有缓存条目生成快照，不扫描
像素、不读盘、不等待加载任务；FFI 读取使用 try_lock，忙时保留上一份数值。
关闭时跳过采样与绘制。冻结期间数值也会冻结，并非独立性能插件。

| 浮窗字段 | 含义 |
|---|---|
| TOTAL | ready + idle / 192 MiB 共享缓存上限 |
| READY | 预载结果，包含像素、压缩数据和附加信息 |
| PIX / ZIP | 预载解码像素 / 压缩数据 |
| LUA LOAD | 当前脚本绑定的路径：成功预载完成数 / 已提交的计划数，单位为个 |
| LUA PIX / ZIP | 上述路径中，仍在预载器内的解码就绪数 / 仅压缩数据就绪数，单位为个 |
| IDLE | 图片管理器保留占用 / 当前动态闲置限额 |
| CPU | 保留的解码像素 / 动态可用额度（闲置限额扣除 GPU、压缩及附加信息） |
| GPU | 闲置 GPU 纹理估算 / 闲置 GPU 限额 |
| IDLE ZIP | 已用图片的压缩备份 |
| HIT GPU | 已存在 GPU 纹理的累计复用次数 |
| CPU / ZIP | 解码备份 / 压缩备份的累计命中次数 |
| MISS | 查找时 GPU 纹理未驻留次数，不等于读盘次数 |
| EVICT | 累计缓存淘汰次数，不是剩余内存 |

容量单位都是 MiB；HIT、MISS、EVICT 从本次游戏会话开始累计。TOTAL 不是整个程序内存，
不包含正在显示的 GPU 纹理、显示缓冲、离屏目标、音频等；部分小型附加信息
计入总量但没有单独一行，因此显示子项的四舍五入和不一定等于总数。
CPU 额度随共享池及预载预留变化，不是整个进程 CPU 内存限制。

`LUA LOAD 35/100` 表示当前仍有脚本绑定的 100 个不同路径中，35 个成功准备过像素或压缩源。
同一路径多次绑定只计一次；包括游戏剧情和 UI 的 `bindSurface/Async` 请求，
不把独立章节遮罩／动画提示计入。提示资源后来也被 Lua 绑定时才纳入统计。
分母是游戏脚本已经提交的计划，不是引擎猜测的整个章节资源总数。

完成数在结果交给渲染器后保留，因此不等于当前常驻数量；`LUA PIX/ZIP` 只表示尚在
预载器里的就绪资源，不包含已交给渲染器或保存在 GPU/CPU 复用缓存里的资源。
解绑后移出这组计数，脚本重新发起加载时重新计进度；未完成、缺失、取消中的未完成项
以及容量拒绝不算成功，因此不保证总能达到 100%。换游戏时清零。

计数随加载器现有记账更新，HUD 只读共享账本，不反向锁加载器。快照保留原 20 项 ABI
前缀，扩展为 24 项。仍沿用原浮窗开关和默认关闭行为，未改变缓存优先级或容量。

浮窗是宿主最终画面的诊断绘制，可能随截图／画面捕获保留下来；正式截图和
纯性能对比应关闭。它不会改变缓存策略、shader 字节或游戏字体设置。
