# 显存压力下人物底图／表情缺失（2026-09-20）

## 已确认的实机故障

`2026-09-20 13-07-54.mp4` 的 Toshiue 开篇出现只有身体、没有表情；约 8 秒后
换姿势恢复。对应 `toshi_01` 的 block_00190 至 block_00198，涉及 z2/fa 下
的 a0016、a0005、b0006、b0011。只读提取到 build 检查，表情 PNG 含正常
五官与透明像素。没有修改游戏归档。该录像当时的连续故障日志未保存，尚不能
把录像的每一次缺脸都确认为同一原因。

随后用户现场复现相反现象：只有五官，人物身体消失。立即保存日志至
`build/hardware-logs/20260920-134840-companion/host.log`。
`ren_z2a0200.png` 已解码为 672×2076 RGBA（5,580,288 字节），却连续上传
失败。日志共记录此文件 520 次 upload-deferred；末尾多个 5 秒窗口中每次
20 次上传均失败，没有重新读盘或重新解码。同期还曾有背景和 CG 上传失败。

截图闲置 GPU 缓存约 31.2/32 MiB，物理 VMEM 108/112 MB；账本中 CDRAM
live 96,993,280 字节，uncached live 19,922,944 字节。旧缓存只按逻辑额度
淘汰，没有把实际 GPU 上传失败接到闲置纹理回收，因此在额度以内也能持续
缺图。现有日志不能分辨每次分配失败究竟是区域耗尽还是连续块碎片不足。

## 修正

- 静态图片上传失败时记录重试需求及最大失败图片的所需空间。
- 先完成本帧所有资源的保活标记，再按 LRU 回收闲置 GPU 纹理；不在遍历
  当前场景途中淘汰“本帧稍后才会用到”的纹理。
- 复用原视频分配失败回收机制，单次上限 16 MiB；保留已有 CPU 解码备份
  与压缩源，沿用 host GPU 等待／延迟销毁，下一帧重试。
- 静态页面存在未完成上传时也重新构建绘制列表，不只等待下一句或动画变化。
- 不修改 shader、图像透明度、缓存额度、堆大小或已验收字体优化。
