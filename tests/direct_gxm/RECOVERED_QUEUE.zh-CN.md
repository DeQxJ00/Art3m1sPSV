# 人物与头像同屏的目标切换

旧路径在每次 recovered packet 需要重新打开目标时执行 `sceGxmFinish`。
人物与头像之间穿插普通遮罩分组时，这会在一帧中途等待 GPU，阻断
下一帧 CPU 场景构建与 GPU 渲染的重叠。

在宿主已启用离屏排队的模式下，packet 的目标切换现只结束当前
scene 并标记 GPU 工作未完成。顶点 arena、纹理退休、读回及下一帧
重用仍受原完成屏障保护；EndScene 失败、禁用排队或非排队构建
继续同步完成。诊断文件 `recovered-queue.off` 可恢复 packet 的等待路径。

恢复主目标或显式人物父目标时，排队模式可以重新附加同一模板
缓冲，避免随后为了绘制头像再次拆分 scene。模板存储不重新分配，
软遮罩原有 store/load 语义保留。仅含硬遮罩的 packet 还使用向外
扩展到 32 像素 tile 的保守 clip；精确边界仍由原模板遮罩决定。

## 验证

- `scripts/test-recovered-packet-state.py`：128 个变化 affine 的顶点
  字节检查、10 万步状态差分、102 个 API 故障注入，以及排队资源
  保留、强制回退、EndScene 失败后的完成处理通过 ASan/UBSan。
- `recovered_clip_region_test.cpp`：随机裁剪矩形的所有可见采样点
  都保留在粗裁剪区域内；不改变模型顶点和实际裁剪边界。
- `scripts/build-recovered-probe.py --queued` 与实机 runner：12 组
  同场景同步/排队对照，覆盖硬/软遮罩、affine、不同父深度、重复
  人物遮罩分组与主目标头像切换；全帧 RGBA 均为 0 字节差异。
  另有不支持透明度的恢复路径。动态系统叠层只在像素探针时隐藏。

这些像素对照证明本次调度变化与同步参考一致，不代表不同父深度
之间完全等价，也不是实际动画模型逐帧的自动像素 oracle。

## 2026-10-16 完整宿主实机结果

同一存档槽 5、人物和头像同屏，CPU 444 / GPU 222，10 秒预热后
采样至少 30 秒，不推进对话。三轮源存档 SHA-256 一致且内容未变，
临时设置均已恢复；完整性能叠层在这些采样中保留。

| 路径 | 平均 FPS |
| --- | ---: |
| 同步 packet 切换基准 | 21.88 |
| packet 目标排队 | 32.82 |
| 排队并恢复目标时预附加模板缓冲 | 37.43 |

最终版本提升约 71%。抽样头像 scene 准备从约 24ms 降到约
0.03ms；CPU 逻辑及场景准备仍约 16ms，呈现部分约 11ms，后者
包含下一帧开头约 5ms 的 GPU 完成等待，不能把它当成纯 GPU 时间。
尚未达到 60 FPS；早先连续运行中的约 13 FPS 不作为这次同条件基准。
